Log cleanup strategy

The cleaner parses vanilla, Forge and Fabric header formats; lines without a header are treated as a continuation of the previous entry (i.e. a stack trace).

✅ Keep

  • ERROR / FATAL (highest priority)
  • WARN
  • INFO lines with keywords
  • First 12 entries (environment info)
  • Last 12 entries (what happened before the crash)
  • 3 entries of context before each error

🗑 Drop / compress

  • DEBUG / TRACE
  • Known INFO noise (resource reloads, sound init, chat…)
  • Identical messages (after number normalisation) merged into (×N)
  • At most 12 frames per stack; the rest are folded

When over the character cap, lower-priority entries are dropped first; ERROR / FATAL are touched last. The default cap is 14,000 characters (≈4–5k tokens) because Groq's free tier and GitHub Models have small per-request token limits.

Crash report extraction

crash-reports/

Takes the newest report and extracts the main stack, Head, key System Details and Suspected Mods.

hs_err_pid*.log

JVM native crashes: keeps the # summary and the native stack.

Mod list

Fabric / Quilt's Loading N mods: block is condensed to one line. Forge / NeoForge latest.log usually lacks a full list; when a crash report exists, the tool tries to fill it in from the Mod List: section.
