Log 整理策略

整理器會解析 vanilla、Forge、Fabric 三種標頭格式；沒有標頭的行視為前一筆訊息的延續（也就是堆疊追蹤）。

✅ 保留

  • ERROR / FATAL（最高優先）
  • WARN
  • 含關鍵字的 INFO
  • 前 12 筆（環境資訊）
  • 後 12 筆（崩潰前的動作）
  • 每個錯誤之前的 3 筆上下文

🗑 丟棄 / 壓縮

  • DEBUG / TRACE
  • 已知 INFO 雜訊（資源重載、音效初始化、聊天…）
  • 相同訊息（數字正規化後）合併為 (×N)
  • 每段堆疊最多 12 個 frame，其餘折疊

超出字元上限時，依優先級由低到高丟棄；ERROR / FATAL 最後才會動到。預設上限 14,000 字元（約 4–5k tokens），因為 Groq 免費層與 GitHub Models 的單次 token 限制較小。

崩潰報告萃取

crash-reports/

取最新一份，擷取主堆疊、Head、System Details 重點與 Suspected Mods。

hs_err_pid*.log

JVM 原生崩潰：保留 # 摘要與原生堆疊。

Mod 清單

Fabric / Quilt 的 Loading N mods: 會壓成一行。Forge / NeoForge 的 latest.log 通常不含完整清單；有 crash-report 時，會嘗試從 Mod List: 區段補上。
