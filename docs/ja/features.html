ログ整理の方針

vanilla・Forge・Fabric のヘッダー形式を解析し、ヘッダーのない行は直前のエントリの続き（スタックトレース）として扱います。

✅ 残すもの

  • ERROR / FATAL（最優先）
  • WARN
  • キーワードを含む INFO
  • 先頭 12 件（環境情報）
  • 末尾 12 件（クラッシュ直前の動作）
  • 各エラーの直前 3 件のコンテキスト

🗑 除去・圧縮するもの

  • DEBUG / TRACE
  • 既知の INFO ノイズ（リソース再読込、サウンド初期化、チャット…）
  • 同一メッセージ（数値正規化後）は (×N) に統合
  • スタックは最大 12 フレーム、残りは折りたたみ

文字数上限を超えると優先度の低いものから削除し、ERROR / FATAL は最後まで残します。既定は 14,000 文字（約 4〜5k トークン）。Groq の無料枠はリクエストあたりのトークン上限が小さいためです。

クラッシュ報告の抽出

crash-reports/

最新のレポートから、メインスタック、Head、System Details の要点、Suspected Mods を抽出します。

hs_err_pid*.log

JVM ネイティブクラッシュ：# の要約とネイティブスタックを保持します。

Mod 一覧

Fabric / Quilt の Loading N mods: は 1 行に圧縮します。Forge / NeoForge の latest.log には通常 Mod 一覧が含まれないため、crash-report があれば Mod List: から補完を試みます。
